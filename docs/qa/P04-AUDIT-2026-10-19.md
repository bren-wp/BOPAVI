## What was actually inspected

The complete native source inventory, manifest/Gradle/Xcode configuration, CI workflow, generated resource inventory, asset build warnings, test/dead-code checks, public marketing documents and native save import/export contracts were reviewed at source/static level. Focused function-level inspection covered `GameView.kt`, `GameCanvas.swift`, `MainActivity.kt`, `GameController.swift`, `BopaviCore.swift`, `GameSimulation.kt`, `LevelEngine.kt`, both `ProgressStore` implementations, both `Soundscape` implementations, native test harnesses and release helpers.

Existing baseline green `tools/audit_native_dead_code.py` scanned **12 native source units, 286 private declarations and 46 explicit Kotlin imports**. This **does not prove** that all paths, reflection, frameworks or unused resource bytes have been exhaustively proven unreachable. The baseline iOS logs actually reported an orphan image catalog warning despite a passing static audit.

The automated CI already covers Android lint/JVM tests, Android 15/16 emulators, iOS Release+Debug simulator builds, Swift migration/regression tests, generated art/audio parity, local source contracts and publishing guards. No coverage of physical devices, every older Android SDK or screen-interruption permutation is claimed.

## Identity, data and release safety

- Keep `com.brendigo.bopavi` Android application ID and iOS bundle ID. Do not change exported JSON v1–v6 compatibility, preference keys, achievements/currency remnants, user scores, local player history or approved art input.
- Android `minSdk 26`, `targetSdk 36`; no INTERNET permission in manifest; `android:allowBackup="false"`. No runtime ads, third-party analytics or user sign-in observed in the inspected native dependency/runtime path.
- iOS uses `UserDefaults` local storage; this audit **did not validate** OS backup/cloud backup policies or power-loss durability. Avoid blanket backup resets.
- The only runtime dependency in Android `app/build.gradle.kts` is platform Kotlin/Android; JUnit 4.13.2 is test-only. No reason to introduce third-party dependencies for these fixes.
- Native v0.2.24/build129 is a **candidate**, not a Play-signed artifact or approved store submission. Keep debug APK, unsigned AAB, simulator ZIP and unsigned iPhone device ZIP categorically distinct. Release SHA256 must be recomputed for **candidate outputs only after green CI**.

## Required reproducible performance / robustness campaign

1. Use the same representative Android 8/10/15/16 or lowest-supported API device(s), record device model, Android version, thermal state, refresh rate, battery/charging state, exact Git SHA and cold/warm start for both builds. Use Perfetto/frame timeline, `dumpsys gfxinfo com.brendigo.bopavi framestats`, `dumpsys meminfo`, and local `am start -W` timing with repeated Home→Flight→Pause→Results→Retry. Do not clear a user's app storage.
2. Profile iOS with Instruments **Time Profiler, Allocations, Core Animation and Energy Log** on identical iPhone/iPad hardware for both baselines, 30/60/90/120 Hz where supported. Record full-run median and distribution (not a single best sample). Explicitly compare static/alpha gradient colors and the screenshot diff for Home, Flight Preview, Active Flight, Pause and Results.
3. Run 20+ controlled cold-start/foreground-background transitions and real interruption tests with verified existing best score, best food, counters and upgrades; compare after restart and an induced process termination. Correlate any real crash with Android stack trace/ANR/OOM/tombstone or iOS `.ips` plus matching dSYM.
4. Exercise invalid/corrupt JSON v1–v6 import, extremely large counters, replay, rapid taps, audio enable/disable, and layout accessibility checks on every supported platform. Source tests alone are not enough.
5. Verify Android 15/16 emulator CI and iOS Debug+Release simulator CI on the exact PR head. Confirm older Android and physical-device coverage before public certification. Hash every resulting candidate asset and verify AAB signing state; store upload signing/approval is a separate private publisher step.
